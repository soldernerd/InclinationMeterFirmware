Firmware overview

STM32G0B1 inclination meter. About 75 source modules, grouped here into 13 subsystems. Start on Overview; click any box. The other tabs show how the firmware starts and runs, and every module with every arrow.

Reading the diagram

Each box is a group of related source files. An arrow means "uses": the box at the tail includes code from the box at the head. Rows go from the program's entry point at the top to the hardware at the bottom. Dashed arrows point upward (a lower layer calling back, for example a callback).

Click a box to see its modules in plain words, and which boxes it uses (green) and which use it (orange).

To keep the picture readable, arrows from Boot and entry (main starts everything) and arrows into the HAL, pure maths, shared state and vendor libraries (everything uses those) are hidden until you select a box, or:

The path of a reading

AD9833 sine→ sensors →ADS131M04 ADC (4 channels)→ DMA →svc_displacement: sums per batch→Math: phasor, ratio, zero, k→Hann window + quality flag
then toLIVE screen (app_display)andHost API: Measurements, Topics→USB / BLE / UART→ host app

The ADC produces 20,833 samples per second. The sample callback only adds numbers into a batch (cheap, runs in the SysTick drain); the maths runs once per 64-cycle batch (40.7 per second) in the normal loop.

A request from the host

USB / BLE / UART bytes→transport reassembles a packet→svc_api dispatcher checks it→a handler in svc_api_res_*→the module that owns the thing→ response into the transport's TX queue

Boot order

The init calls in Core/Src/main.c, in the order they run:

    The main loop

    After boot, app_scheduler_run() never returns. Each pass it runs every task that is due (table in App/app_scheduler.c):

    taskruns

    Order matters inside a tick: input is read before the UI acts, the UI before the display draws, and the transports before the API so a command received this tick is answered in it. A separate 1 ms SysTick interrupt drains the ADC, refreshes the watchdog (only while the loop makes progress) and keeps time; a timer interrupt toggles the display's VCOM line, which must never stop.
